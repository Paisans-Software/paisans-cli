# Mbin reads the deployment's mail settings

Date: 2026-10-11. Status: approved by the founder in session.

Mbin sends mail through Symfony Mailer, and until now the toolkit rendered
none of its mail settings, so every app ran on the image's baked placeholders:
`MAILER_DSN=smtp://mailserver`, a host that does not exist in the stack, and
sender and contact addresses at `mbin.domain.tld`. The `mbin` kind now reads
the deployment's `smtp` block, with the app's own block overriding it field by
field, the way `pocket-id` and `uptime` already do.

## Scope

In: `kinds.SendsMail`, the mbin `.env` template, a new `settings.contact_email`,
`MBIN_LOCKED_SETTINGS`, `MBIN_PRIVATE_INSTANCE` for a gated app, four `validate`
rules, the example, the README and the visibility gate spec.

Out:

* **The fork's locked settings feature.** It is a separate change in the
  paisans fork of Mbin. The toolkit renders the variable now; an image
  without the feature ignores it.
* **Any check that mail is delivered.** Nothing here talks to a mail server.

## What Mbin mails

Every member signs in through the identity provider, so Mbin sends little:

* the `/contact` form, to `KBIN_CONTACT_EMAIL`;
* resending an activation link, for an account not yet verified;
* a password reset and an email change verification, which the fork is
  refusing for an account the identity provider controls.

It sends no notification or digest mail.

## `paisans.yaml`

```yaml
apps:
  talk:
    kind: mbin
    settings:
      contact_email: admins@example.org   # optional
    smtp:                                 # optional, overrides field by field
      from_address: talk@example.org

smtp:
  host: smtp.example.org
  security: starttls
  username: talk@example.org
  from_address: hello@example.org
```

The password is `apps.<app>.smtp_password`, else `external.smtp_password`, as
for every kind that sends mail; `init` lists the second as owed once an Mbin
app resolves a host and has no password of its own.

## The rendered `.env`

| Variable | Value |
|----------|-------|
| `MAILER_DSN` | `smtps://user:pass@host:port` for `security: tls`; `smtp://user:pass@host:port?require_tls=true` for `starttls`; `null://null` with no host |
| `KBIN_SENDER_EMAIL` | the effective `from_address`, else `noreply@<hostname>` |
| `KBIN_CONTACT_EMAIL` | `settings.contact_email`, else the sender |
| `MBIN_LOCKED_SETTINGS` | every Mbin database setting the file sets, comma separated |
| `MBIN_AUTHORIZED_FETCH` | `settings.authorized_fetch`, true when absent (amended 2026-10-11) |
| `MBIN_PRIVATE_INSTANCE` | `true`, only when the app is gated |

The DSN is built in Go (`mailerDSN` in `internal/render/mbin.go`). The port is
`PortOrDefault()`. The username and password are percent encoded except for
RFC 3986 unreserved characters, since Symfony's `Dsn::fromString` splits the
DSN with `parse_url` and then `rawurldecode`s each part; with no username
there is no userinfo. Fully encoded, the DSN holds nothing Docker Compose
reads specially in an `env_file`, so `envquote` writes it bare. The image's
Symfony Dotenv never overrides a variable already in the process environment
(`Dotenv::bootEnv`, `overrideExistingVars` false), so what compose passes is
what Mbin reads.

Verified: the rendered `.env`, with a password of
`` a@b:c/d?e#f%g'h"i$j k+l&m=n\o ``, was passed as an `env_file` by Docker
Compose v5.4.0 to a PHP 8.4 container, where symfony/mailer v7.4.14 parsed it
back to the same user and password, built an `EsmtpTransport` with TLS
required for `starttls` and implicit TLS for `tls`, a `NullTransport` with no
host, and accepted both addresses in `Address`.

`from_name` is not used: Mbin always sends as `new Address(KBIN_SENDER_EMAIL,
KBIN_DOMAIN)`.

## Locked settings

The list is `KBIN_DOMAIN`, `KBIN_SENDER_EMAIL` and `KBIN_CONTACT_EMAIL`,
`MBIN_SSO_ONLY_MODE` when the app has a client at the identity provider, plus
`MBIN_PRIVATE_INSTANCE`, `MBIN_AUTHORIZED_FETCH` and
`MBIN_USE_FEDERATION_ALLOW_LIST` when gated. Amended 2026-10-11:
`MBIN_AUTHORIZED_FETCH` is rendered and locked always, from
`settings.authorized_fetch` (true when absent), and the test also checks
every locked name against the fork's lockable list, since Mbin answers every
request with an error on a name it cannot lock. It is derived from what the
template renders: `TestMbinLockedSettingsAreRendered` renders the file gated
and not, and checks that every locked name is a key it sets, and that every key
it sets that is a field of the fork's `SettingsDto` is locked. A passthrough
key under `config` is the operator's and is not locked.

**Sign in is the identity provider's alone.** With a client at the provider,
the `.env` sets `SSO_ONLY_MODE=true`. The image's defaults leave it empty and
`KBIN_REGISTRATIONS_ENABLED` true, which keeps Mbin's own password
registration at `/register` open, and working mail delivers its verification
email: anyone who could reach it could then make an account the provider and
its member group never see. `SSO_ONLY_MODE` closes `/register`
(RegisterController.php:29); accounts are still made on first sign in. Its
environment variable and its setting have different names, so the lock names
the setting, `MBIN_SSO_ONLY_MODE`, and `mbinSettingEnv` records the variable
that feeds it.

## Validate

| Rule | Level | When |
|------|-------|------|
| `mbin-without-smtp` | warn | no SMTP host resolves: mail is discarded, the app works |
| `mbin-smtp-without-sender` | warn | a host resolves and no `from_address` does |
| `mbin-smtp-from-not-an-email` | refuse | the effective `from_address` is not an address alone |
| `mbin-contact-email-not-an-email` | refuse | `settings.contact_email` is present and not an address alone |

The two refusals are values Symfony's `Address` throws on, so no mail could
ever be sent with them. `smtp-on-a-kind-without-mail` no longer fires for an
Mbin app, and an Mbin app's own `from_address` makes its domain a mail name
for `dns init`.

## Known limits

* **Until the pinned image carries locked settings, the database wins after
  the first admin save.** Amended 2026-10-11: closed. The kind defaults to
  `stack-1`, whose first promotion, 1.15.0+paisans, carries the feature. Mbin's `SettingsManager::save` writes every field of
  its settings, the addresses included, and from then on reads the row. A
  changed `contact_email` then reaches the app only through its settings page,
  and a changed `from_address` not at all, since the sender is not on that
  page. `MAILER_DSN` is not a database setting and always follows.
* **A `contact_email` needs a mailbox that receives.** Nothing checks one.
  At `community.domain` in particular, `dns init` publishes a null MX unless
  the domain is a mail domain, so mail to an address there is refused until
  mail is set up and the domain is listed in `community.mail_domains`.
